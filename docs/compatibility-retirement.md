# Compatibility Retirement Ledger

This is the canonical inventory for DockPipe compatibility debt. It records accepted legacy
inputs, aliases, layouts, ignored values, and recovery readers so that a later change can retire
exactly one surface without treating a repository search or an old task record as removal
authority.

The ledger is descriptive only. An entry is maintained until a separately approved change proves
the entry-specific retirement gate below. This file does not deprecate, warn on, migrate, remove,
or change any behavior.

## Evidence Rules

- **Active source** is current engine, core-asset, schema/editor, or package code. It proves behavior
  exists, not that external callers do or do not exist.
- **Current promise** is current canonical documentation or CLI/tool help. It is part of the public
  contract until changed in the same separately approved retirement slice.
- **Current caller/fixture** is an authored config, package script, CI caller, or test in this
  checkout. Its absence is only negative repository evidence; it does not prove downstream absence.
- **History** can prove the first source commit found by `git log -S`, but it cannot grant retirement
  authority. Every identified engine surface first appeared after tag `v0.5.8`; the checkout says
  `VERSION=0.6.0`, but there is no `v0.6.0` tag. Therefore the ledger records source-introduction
  commits and treats the minimum released version as **unproven** unless a package version is
  explicitly stated.
- **Closed evidence** in task archives, promotion packets, VM qualification records, or old handoffs
  is immutable context only. It cannot authorize a retry, migration, cleanup, or compatibility
  removal.
- **Missing proof** is recorded as missing. It must never be inferred from a clean search result.

## Retirement Proof Profiles

Every gate is a new, separately approved slice for one ledger ID only.

| Gate | Exact proof required before that one entry can be retired |
| --- | --- |
| `CONFIG` | Name the exact old key/value and canonical replacement; prove no authored repo, package, fixture, generated example, schema, or editor caller remains; add focused precedence and rejection tests; update canonical docs/help and editor support together; establish a documented downstream support/version floor. |
| `CLI` | Name the exact command or flag; prove no repo/package/CI/fixture caller remains; test the canonical command and explicit rejection of the old token; update help and CLI reference together; establish a documented downstream support/version floor. |
| `LAYOUT` | Name the exact old path and replacement; prove all readers/writers and packaged fixtures have migrated; test precedence plus explicit old-layout rejection using fabricated roots; inventory any real state only under separate authority; never combine retirement with deletion. |
| `STATE` | Name one exact owner/schema/cohort; prove its current writer is gone, all supported readers have migrated, restart/divergence/permissions/link tests pass, and retained real state has been inventoried under separate read authority. Removal, cleanup, and migration remain separate gates. |
| `PACKAGE` | Name one package-owned alias/wrapper; prove no current package/workflow/CI/tool caller remains; add canonical-input and old-input rejection coverage in that package; update package docs/models/fixtures together; establish the package support/version floor. |
| `RECOVERY` | Name one historical schema/resource reader; prove no supported recovery or cleanup input can still carry it, preserve exact negative execution authority, and pass the package's complete fabricated recovery matrix. Historical packets and hashes are evidence only. |

## Classified Non-Entries

These scan hits are not retirement candidates in this ledger:

- ordinary documented CLI synonyms such as `-h`/`--help`, `--template`/`--image`, and
  `--act`/`--action` are current user-interface vocabulary, not marked transition debt;
- top-level `resolver` is the current tool/profile architecture field; the narrower step-level
  runtime-pairing fallback is retained explicitly as `CR-041`;
- `kind: host` is current public execution behavior with many authored callers. Research discussing
  a possible future `runtime: host` migration is not an implemented replacement or retirement plan;
- unknown `runtime.type` preservation is forward-compatibility behavior, not an old accepted name;
- banned workflow keys including `skip_container`, `primitive`, `default_runtime`, and
  `default_resolver` are already rejected, with `skip_container` covered by
  `src/lib/domain/workflow_test.go:187`; they are negative evidence, not maintained aliases;
- generated third-party Tauri schemas under `packages/pipeon/apps/pipeon-desktop/src-tauri/gen/`
  belong to that dependency/tool surface and are not DockPipe-authored promises;
- package compatibility probes and fingerprints (for example backlog remote compatibility) describe
  interoperability results, not backward-compatible DockPipe inputs;
- `AWS_ENDPOINT_URL_S3` in the R2 uploader is the AWS CLI's endpoint input, not a DockPipe alias for
  `R2_ENDPOINT_URL`; the package declares both for different upload clients;
- old DorkPipe/Pipeon context paths found only in negative fixtures are not active fallbacks;
- `templates/core`, materialized `bundle/core`, and `bundle/workflows` are current installed layouts;
  only the project authoring fallback `templates/<name>` is ledgered above.

## Maintenance Rule

When a compatibility surface is added, discovered, warned on, or materially changed, update this
ledger in the same source change. A retirement slice changes one ID only, records the proof profile
results and version decision here, and updates every named canonical/help/schema/editor/package
anchor. Inventory never authorizes removal, migration, cleanup, live inspection, or a retry.
