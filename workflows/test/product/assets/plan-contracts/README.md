# Source-owned qualification plan schema contracts

This additive consumer compiles the existing qualification Source owner directly
and supplies actual pinned PipeLang.Json Reader/Indexer effects. PlanSuite owns
all case IDs, JSON fixture construction, expected acceptance/errors, cancellation
assertions, cleanup and the result verdict. Native code composes adapters, supplies
a genuinely cancelled token and serializes the Source report. It has no driver,
process, evidence, coverage, resume or active-runner policy.

All 18 cases pass locally on Linux normally and with the reader, generated Source
and native caller under ASan/UBSan/leak checks. Every body and independent cleanup
runs, all documents close, and containment confirms descendant removal. This uses
the explicit caller profile below and an immutable additive Testing artifact; it
does not establish Windows/macOS acceptance or change an active SDK pin/default.

Select an installed SDK with explicit CMake values `PIPELANG_SDK_PREFIX`,
`PIPELANG_SDK_MANIFEST_SHA256`, `PIPELANG_JSON_SHA256` and
`PIPELANG_TESTING_SHA256`. Build target `qualification_plan_probe`; it needs no
runtime arguments. It requires the qualified additive `IProbeTestCase` and
`TestRunner.RunAllProbes` API in PipeLang.Testing. Select that immutable source
artifact with an absolute `PIPELANG_TESTING_LIBRARY_ROOT` and its required
`PIPELANG_TESTING_SHA256` descriptor hash. If no root is supplied, the installed
SDK's Testing directory is selected and must provide the same capability; there
is no API fallback. Never select the owning source checkout or copy its library
implementation into this consumer. `SANITIZERS=ON` instruments generated units
and the actual installed JSON reader source.

The caller explicitly selects the existing registry predicate profile of
33,554,432 normal evaluation steps per synchronous invocation through
`TaskOptions.evaluationStepsPerSegment`. The complete 18-case/68-plan-variant
suite runs once with `RunAllProbes`, sharing that one finite allowance across
nested helpers. There are no artificial waits, per-case native pump or inserted
budget resets. SDK/global default and cleanup remain 65,536; initialization,
strings/collections, JSON/index bounds and physical containment are unchanged.
The report records all three evaluation values. The actual default 65,536 run
failed before completing the bounded corpus; this is an explicit caller resource
selection, not a claim the default passes or that maximal schema inputs fit.
Host containment remains supplied independently by the qualification workflow.

Only the cancellation case supplies the separate genuine method-scoped probe
token to policy validation; ordinary cases use their normal token. All 18 IDs,
expected outcomes, fixtures and assertions are retained. The existing explicit
32MiB index reservation remains within the unchanged reader aggregate ceiling.
The positive digest cache validates every node's kind/text/length and fully
checks distinct or uncached spellings. It holds at most 4096 valid 64-byte
spellings, resets per validation and bypasses insertion at capacity, without
introducing an input acceptance cap. This avoids repeated checks of identical
artifact/source pins while preserving distinct-pin validation.

PlanPolicy matches plan/v1 schema admission from the active Python contracts. It
retains lowercase hex pins, integer-form deadlines, registered Unicode platform
IDs, optional defaults, opaque configuration, unknown fields outside exact
2-member dependency objects, and feature selections beyond64. Dependency path
uniqueness uses decoded borrowed strings, including paths larger than4096bytes.
Source builds those fixtures through <=4096-byte appends, without enlarging a
Source string or constructing a native schema fixture factory.

The active Python runner remains in place while the wider migration boundary is
unfinished. Eventual local runner migration is already authorized by the broader
goal once parity and required proofs are complete; this consumer introduces no
additional approval gate, SDK/default switch or release. Source pin/file
verification, overlapping driver ownership, aggregate run budgets, receipt
admission, evidence hashing, coverage, resume and interruption orchestration
remain in their existing owners. Schema admission alone does not qualify a plan
for execution or produce product coverage.
